# 口播精剪、访谈与字幕

## 模式：节奏和内容取舍是两件事

默认 `tight` 口播精剪，不默认截成 60 秒。用户只说“剪一下”时保留完整观点，主动检查重复、改口、水词和气口；有目标时长再按目标选主题。

| 模式 | 内容标准 | 停顿候选起点 | 两侧缓冲 |
|---|---|---|---|
| light 轻剪 | 完整内容，修明显重录与长空白，保留口语风格 | 0.8s | 0.20s |
| tight 精剪（默认） | 完整核心观点，删无意义重复、残句、口头禅、拖节奏的例子 | 0.4s | 0.12s |
| highlight 重点版 | 先选一个主题，再精剪；约 30–60 秒仅是常用目标 | 0.4s | 0.12s |

这些数值是找候选，不是自动删除阈值。强调、思考、换气有表达作用时保留。用户偏好覆盖默认值，不能强制把所有停顿缩成同一长度。

## 顺序：修字 → 分类精剪 → 重读 → 编译 → 切口验收

原始 ASR 不覆盖。先检查人名、数字、术语；可用 `transcribe --glossary` 提示识别。无法用原音或用户词表确认的修正列为存疑，不把语义推测当事实。修字不能造词级时间：换写法可以沿用整个词的时间，拆分音节需真实重新对齐。

先读全文，按论点列“核心观点、必要前提、保留句、删除句、理由”的清单，再做下面的分类检查。不要读到一句就直接删，后文可能依赖它的前提。清单由宿主填写，规则脚本不能代替它。

运行 `editorial.py analyze` 生成停顿、口头禅和相邻重复候选与稳定 word_id。脚本不会理解跑题和观点，不会直接删除。WorkBuddy 应完整阅读转录，分轮检查：

1. 重复：重起句、重复解释。通常保留更完整的一遍；“天天”“看看”等正常构词和强调不能当口吃删除。
2. 残句与改口：保留最终说法，检查数字、否定、限定条件是否跟着保留。
3. 水词与口头禅：“这个、然后、就是、对吧”等只有不承担指代、因果或转折时才删；密集连说优先检查。不能全局替换再剪声音。
4. 结构：背景 → 观点 → 必要例子/论据 → 结论。冗长背景、重复例子、偏题可以删；不同观点需保留完整过渡。重点版可重排，但注明，不能拼成说话人没有表达的因果。
5. 节奏：结合实际音轨静音与词间隔，压缩拖沓气口；没有 ASR 文字不证明没有声音。音乐/环境声会影响检测。

逐项写 `decisions.json`，delete 必须有理由和证据说明；不确定项 keep 并注明。无需让小白逐项填写或为可恢复的本地草稿反复批准。大幅改变论点/含义时先解决内容歧义。

每轮的发现与保留原因写进 `semantic_review`，记录已读范围及存疑点。不得用“脚本候选零警告”代替语义检查。剪完按输出顺序重读保留词：人称是否一致，句首是否缺主语，转折是否悬空，枚举数量是否匹配。只有 ASR 漏掉某一点，不得据此说原片缺点或编出那一点。

## 删词与字幕时间轴

`editorial.py build` 合并删除范围，拒绝切进保留词；按保留词重建 output SRT，映射后按输出词轴重新拆句；这是候选字幕。全片渲染前由宿主按完整短语写 phrases.json，调用 editorial captions 生成最终字幕。文本已移除删词，可跨切口接续短字幕，避免把“面向”等单独闪成一条。不要对被删词的长句字幕仅裁时间，这会让删掉的字仍显示。零时长词不适合精切，工具阻止附近删除；字幕将它并入相邻有时间的词组，不伪造单字时间，仍须校对。

语义删除用连续 word_ids；不要按汉字数均分时间。一个 ASR token 包含“这个这个”时不能猜其中一半的时间，先对齐或保留。如果边界听起来吞字，把删除区缩回、补缓冲或换整句剪法，不能只修改字幕掩盖问题。

工具支持单源顺序删减。重点选段和重排继续使用 video.py 清单；字幕须基于保留词重建，output 轴跨素材先分别处理再合并。多人访谈先确认身份，本包不声称支持说话人分离或自动追脸。

## 字幕样式与验收

默认 `readable`：1080 宽下 60px 白字、4px 黑描边，每条约 12 字，最多两行。`classic` 是小字通用风格，`accent` 是整条黄字强调风格（不是逐词卡拉 OK）。字体文件可指定；使用电脑现有字体，分享时不打包个人字体。

先用 `style-preview` 看样式并检查脸和平台按钮区域，再做实际短片。字幕位置以字块中心占画面高度的比例设置；78% 只是默认，不保证所有平台安全区。

`cut-report.json` 提供每个拼接点输出时间及前后 0.8 秒听音范围。试听开头、全部切口和结尾；关注词尾、爆音、呼吸突断、音画错位。能看帧不能等同能听音。未听项保留 pending，交付为待验收草稿。视频解码通过不代表逻辑、字幕或音频切口通过。

交付报告分开写量出来的（时长、剪口和字幕检查）、看过的（哪些实际成片帧）、要人听的（切口、术语和逻辑完整性）。没有实际听到音频时不能写“剪口自然”或“无爆音”。借鉴 BaoCut/ChatCut 的复核方法，不调用其运行时。

提高效率：先用 review 阅读全文和词 ID；一次定论点与删留，不手工重数。先校对最终短语字幕，预览后再渲染。只改字幕使用 restyle。
