# 可选功能与问答入口

先收集素材路径、用途、目标时长。已说明的偏好和同项目已认可的设置直接复用；只问缺项。询问是对话，不要求宿主有专用表单组件。第一次最多三个问题，用户回答后把选择记到项目 brief.json，再按需加载对应说明。

## 给用户的简短问题

1. “这次想保留完整观点，还是挑最有价值的片段？可以选：保留原话轻剪 / 去重复和口头禅精剪（推荐）/ 围绕一个重点剪短。大约要多长？”
2. “输出一条完整视频，还是按不同观点拆成几条？画面保留原比例（推荐），还是竖屏、横屏、方形？”
3. “字幕和配乐喜欢哪种？字幕可选清晰白字（推荐）、黄字强调、简洁白字、只导出字幕、不加字幕；配乐可选不加（推荐）或使用你已有的轻音乐。”

已知三项不再问。用户只说“帮我剪一下”时问这些问题；“按推荐来”即 tight、单条、原比例、readable、不加音乐。如用户主动提到 B-roll/MG，再集中问：“要不要补充画面和动画？可以不加、只用已有补充镜头、加简洁标题动画、两者都加。”确认素材路径和插入位置后执行；已明确的选择不重复问。未给时长不强行选两分钟，先看是否有完整论点；用户明确的硬上限必须满足。如果要配乐却没有本地音乐，说明当前支持已有音频，允许用户选不加，不能把付费生成/云端上传作为隐含步骤。

## 选项对应的工作流

| 用户选择 | 实际执行 | 限制 |
|---|---|---|
| 轻剪 / 精剪 / 重点精华 | editorial analyze、review，宿主完整读稿作决定，再 build | 内容判断由 WorkBuddy 做；没有自动爆款评分，不改变原意 |
| 一条 / 多条观点切片 | 每条建立独立决定、时间轴、SRT 与输出子目录 | 先确认数量和每条时长；不默认生成多个文件拖慢任务 |
| 原比例 / 竖屏 / 横屏 / 方形 | video 计划设置偶数 width/height；原比例按 probe 旋转后的显示尺寸；常用1080×1920、1920×1080、1080×1080 | 默认 fit=contain 保留完整画面；cover 会裁边，须确认人物不被切掉；没有人脸追踪 |
| 清晰白字 / 黄字强调 / 简洁白字 | caption_style preset=readable / accent / classic；字号可调 | 字体为本机字体；先看静帧，避免遮脸或越界 |
| 只导出字幕 / 不加字幕 | 前者保留 output SRT，burn_subtitles=false；后者省略字幕字段且 burn_subtitles=false | 只要字幕文件可在 captions 后交付，不必渲染视频；不要执行无用转录 |
| 使用已有轻音乐 | music 本地路径及低音量 music_gain，检查起止与淡入淡出 | 用户须提供可使用的音乐；无内置商业曲库，默认不加 |
| B-roll补充镜头 / 简洁MG标题动画 | 使用 extras.py 对已剪好的无字幕底片添加已有视频/图片，或淡入、上移的文字标题，再烧字幕 | 保留口播与配乐；时间为成片时间；不自动找素材、不生成复杂MG。按需读 extensions.md |
| 已有视频改字幕样式或文字 | video restyle 复用带校验记录的 base.mp4 | 仅字幕变化；剪点、画幅、配乐改变须重做 render；旧版本无底片时也须 render |
| 图片/幻灯片配已有旁白 | 按需读 extensions.md，再使用 image clips 与 narration | 用户主动提出才启用；没有自动PPT解析、自动找素材或在线配音 |

命令和完整字段见 [engine.md](engine.md)，内容策略见 [editing.md](editing.md)。图片与可选在线配音边界见 [extensions.md](extensions.md)。普通口播不加载不使用的扩展。

## 保存选择

复制 [brief.json](../templates/brief.json) 到项目，替换 null 和示例值。它是宿主记录，不是 video.py 的渲染计划；确认后的字段再映射到 edit-plan.json。selected 与 deferred 分开记录，未知的音乐路径保持 null。保存来源为 user、previous_approved 或 recommended；用户的明确回答始终覆盖推荐项。最终交付写清本次启用了哪些功能，尚未人工试听的项目记 pending。
